# LapYield

A web app for kart drivers at Baku City Karting. The driver opens a page on their phone, taps **Start** and drives. Afterwards they get a report showing lap times, estimated fuel and CO₂ per lap, eco and pace scores, a speed map of their best lap and coaching tips for each sector.

There is nothing to install, no account, and no server. Everything runs in the phone's browser, and laps are stored only on that phone. The page is available in Azerbaijani, English and Russian.

## Put it online with GitHub Pages (free, about 5 minutes)

1. Create a GitHub account if you don't have one, then click **New repository**.
   - Name it e.g. `LapYield` and set it to **Public**.
2. Click **uploading an existing file**. Drag in **everything inside this folder**: `index.html`, `css/`, `js/`, `sw.js`, `manifest.webmanifest`, the icons, and `tools/` if you like. Click **Commit changes**.
   - `index.html` must be at the top level of the repository, not inside another folder.
3. Go to **Settings → Pages**. Under *Build and deployment*, choose **Deploy from a branch**, branch **main**, folder **/ (root)**, then **Save**.
4. Wait about 1 minute. The site will be at:
   `https://YOUR-USERNAME.github.io/LapYield/`
5. Open that link on your phone. GitHub Pages uses HTTPS, which phone browsers require before they allow GPS.

To update the site later, upload the changed files to the same repository. The site refreshes within a minute.

### QR code for the track

Once you know the URL, create a QR code for it with any QR generator, or ask Claude to make one. Print it and put it at the track entrance or on the karts.

## How it works

| Step | What happens | File |
|---|---|---|
| Setup | Checks GPS accuracy (waits for ±20 m or better), motion sensors and that the screen stays on (Wake Lock) | `js/app.js`, `js/recorder.js` |
| Recording | Logs GPS about once per second plus the accelerometer 10 times per second. Starts automatically once the kart moves faster than 10 km/h, and stops 45 s after it parks. A 2-second press on the button stops it manually. Saves to the phone every 5 s, so nothing is lost if the browser crashes. | `js/recorder.js`, `js/storage.js` |
| Map matching | Each GPS point is matched to the traced track centreline (642 m measured from satellite imagery; the official length shown on the home screen is 802 m), and a lap is counted each time the kart crosses the start/finish line | `js/analysis.js` |
| Fuel | Speed trace → force (F = ma + drag + rolling resistance) → engine power → fuel, using the calibrated kart model (Honda GX270, 4.5 kW effective) | `js/physics.js` |
| Comparison | Each lap is compared with the simulated **fastest possible** lap (50.1 s) and the **eco line** (53.8 s). To keep it fair, the reference laps are sampled once per second, the same rate as the phone. | `js/analysis.js` |
| Tips | The 14 corners are grouped into 6 sectors. The app finds where you waste the most fuel and lose the most time, and explains how to fix it. | `js/analysis.js`, `js/i18n.js` |

The app also works offline. After the page has been opened once, the service worker (`sw.js`) caches it so it opens at the track without signal. Adding it to the home screen makes this more reliable.

## Testing without going to the track

- **Demo report:** "See a demo report" on the home page analyzes the real session recorded on 8 Oct 2026.
- **Locally:** run `python3 -m http.server 8000` in this folder and open `http://localhost:8000`.
- **Recording flow:** `tools/test_analysis.mjs` runs the analysis in Node (`node tools/test_analysis.mjs`).

## Changing the track or kart model

The track geometry, corners, reference laps and kart settings live in `js/track.js`. That file is generated by `tools/gen_track.py`, which takes its input from the `kart_sim` folder (`kart_sim.py`, `baku_track.csv`). To regenerate it:

```bash
python3 tools/gen_track.py
```

The start/finish position is set by `SF_HINT` in `gen_track.py`, in local metres on the pit straight. If the official line is somewhere else, move it there and regenerate.

## Known limits

- **GPS rate:** phone browsers deliver about one GPS reading per second. Lap times and sector trends are reliable. Exact braking points and single-corner fuel numbers are only approximate.
- **Background recording:** the screen must stay on. Browsers pause GPS when a page is in the background or the phone is locked. The app keeps the screen awake where supported, and otherwise tells the driver to disable Auto-Lock.
- **Single track:** only the Baku City Karting layout traced from the 12 Oct 2025 satellite image is included. If the layout changes, re-trace it and regenerate `track.js`.
